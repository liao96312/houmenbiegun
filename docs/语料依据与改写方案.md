## 二、最重要的发现：项目"生硬"是可以用数字量化的

对 235 条**真人安慰语** 和项目 **106 条手写台词** 做同口径统计：

| 指标 | 真人安慰语 | 项目现有台词 | 差距 |
| --- | --- | --- | --- |
| 长度中位数 | **11 字** | **19 字** | 项目长 **73%** |
| 短句（≤10 字）占比 | **44%** | **12%** | 真人短句多 **3.7 倍** |
| **句尾不打标点（无。！？）** | **80%** | **0%** | ← **最致命** |
| 含「先」字 | 极少 | **62%** | 模板化 |
| 含「别 / 不用」 | 少 | **41%** | 净在纠正对方 |
| 以「嗯」开头 | 少 | **17%** | |

### 结论：项目的句子不是"说错了"，而是"根本不是说话，是在写句子"

**100% 的台词都以句号/叹号收尾**——没有一个例外。而真人 80% 的话**根本不打标点结尾**。
这一条就足以解释为什么读起来像文件、不像人：

| | |
| --- | --- |
| 项目 | `那先别回去。你现在火还没下去，缓一会儿。` |
| 真人 | `别难过 想哭就哭 憋在心里很难受 心疼你呀` |

后者用**空格断句、不打句号、带语气词**。前者是**两个完整句 + 两个句号 + 一个"先"字指令**。

补充：真人倾诉语（n=1656）中位数 **20 字**，**29% 用空格分词分句，82% 不打标点结尾，30% 以「我」为主语**。
也就是说**用户会这样跟你说话**：

```
高三 压力大 失眠 家庭 好累 好想哭
陌生人，真的快坚持不下去了
我快碎成二维码了 只想听三个字。。
一个人抗癌4年了，真的好累
```

而项目现在对「好累」这种输入，回的是 24 字的完整句子。**碾压感就是这么来的。**

## 三、真人安慰语的真相：又短、又重复、又没信息量

235 条真人安慰语的高频词：

```
加油(80次) / 抱抱(12次) / 加油加油(12次) / 好好生活(6) / 一起加油(5) /
好好活着(5) / 别难过(4) / 一切都会(4) / 抱抱你(4) / 天天开心(3)
```

**「加油」一条占了 34%。** 整句重复率 Top：`加油加油加油`(5次)、`加油！！！`(4次)、`加油一起上岸`(4次)。

这是一个很硬的结论，也是我必须告诉你的：

> **公开网络上"真人安慰人的话"极度稀缺，而且水平远低于项目的需求。**
> 原因：真正的安慰发生在私聊里；公开评论区的安慰基本只有「加油 / 抱抱 / 会好起来的」这一档，3-8 个字，零信息量。
> 所以**不能靠抄语料做出"有信息量的温柔"**——语料只能给我们**节奏和语气**，内容得自己写。

顺便：网易云热评里那些看着"很有同理心"的长句，绝大多数是**文案腔**——引用余华/史铁生/《肖申克的救赎》、歌词翻译、排比对仗。我做了过滤，被删的样例在 `审核_被删样例.csv` 里，你可以抽查我的尺子准不准。

## 四、从语料里能直接拿走的 6 条规律（可写成硬规则）

1. **句尾不打句号。** 真人 80% 不打。项目 100% 打。→ 硬编码台词和提示词都要求：**句末不用。！，用空格或直接断**。
2. **中位 11 字，一半以上的话在 10 字以内。** 项目 19 字、只有 12% 短句。→ 改成"**先说一句 10 字以内的话**，说完了才允许补第二句"。
3. **用空格分词分句**（29% 的真人倾诉、25% 的真人安慰都这么做）。→ 这是中文口语在网络上的真实书写习惯，比逗号更像聊天。
4. **语气词要留**（啊/吧/呢/哎/唉/嗯/呀/哦，真人安慰语 27% 含）。项目现在把「嗯」当开头模板滥用（17%），却几乎不用其他语气词。
5. **禁止「先别 / 不用 / 别」这一类纠正句式。** 项目 41% 的台词在纠正对方。真人安慰语里几乎没有"你应该怎样"。
6. **允许"没信息量的温柔"。** 真人的 `抱抱 一定会好起来的`、`好好睡一觉吧晚安`、`没事的兄弟` 没有任何信息量，但有效。项目现在每句都想"说到点上"，反而像在完成 KPI。

## 十一、建议策略（允许偶尔给，但必须稀缺）

产品决定：**允许给一条很小的建议，但频率不能过高**。已写进 `data/prompts.json` 的 `advice_policy`：

- 只在两种情况给：① 对方明确问「怎么办 / 有什么办法」；② 对方连着两三句都在说同一个困境、且情绪已经稳下来
- 只给一条，必须小到今天就能做完、不花钱、不需要别人配合（`先去洗把脸`、`喝口热的`）
- 必须排在共情后面，不允许开头就是建议；一次对话最多两条
- 被明确问到时不允许只回「我也没答案」就结束

实测（deepseek-chat，56 探针）：**小建议率 2%**（稀缺）、**追问时给建议率 67%**（被问到了会给）、**说教率 0%**。

> 过程中的一个坑：`empathy_order` 原本写了 4 步（抓词/命名/正常化/在场），模型就**每轮把 4 步都说一遍**，每条回复都是 4 个碎片、18–30 字。改成「四步是优先级顺序，每轮只用一到两步」后，中位长度从 13 字降到 **11 字**（= 真人基准）。
> **教训：写进 prompt 的每一个“步骤”，模型都会当成必做项。**

完整数据与硬门槛见 `docs/语气评测基线.md`。
