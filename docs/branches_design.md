# 分支语料与陪伴手法解析 · 设计说明

## 为什么做

一期完全依赖大模型自由生成，三个问题：

1. **质量不稳定**：同一句「我好烦」，模型有时接得好、有时说教、有时文艺腔。
2. **冷启动难**：用户在最差的状态下，常常「不知道说什么」，空白输入框反而是一种压力。
3. **没有可解释性**：回复好不好、为什么这么接，用户和运营都看不出来，没法迭代。

## 参考

参考 what.arksec.net 聊天模拟器「选项推进剧情 + PUA 手法解析」的形态：

- 选项推进 → 每一句都经过手写打磨，质量可控。
- 手法解析 → 在对话之外叠加一层「为什么这么说」的拆解。

把它的**方向反过来**：参考站解析的是 PUA 操控手法（让人识别被操控），本项目解析的是**陪伴/倾听手法**（让人看见被接住的过程）。一个是拆陷阱，一个是拆善意。

## 怎么做

### 分支语料 `data/branches.json`

每个场景一棵对话树。节点结构：

```json
"node_id": {
  "companion_line": "陪伴者这一句（手写）",
  "analysis": "陪伴手法解析：为什么这么接，对应哪条倾听原则",
  "options": [{"label": "用户选项", "next": "下一节点 id"}],
  "is_ending": false,
  "ending_type": "loosened | calm | safety"
}
```

- 8 个场景，共 65 个手写节点，每棵树 2-4 个结局。
- 选项只给 2-3 个「真实能说出口的人话」，不给书面语、不给正确答案感。
- 结局分三类：`loosened`（松了一点）/ `calm`（今晚先到这儿）/ `safety`（安全转介）。
- 安全结局：出现自伤自杀信号时退出场景感，给现实援助热线（中国大陆：12356；立即危险拨打 110 / 120）。

### 写作原则（继承一期 Prompt 调优结论）

- `companion_line` 像现实里能说出口的短句，不文艺、不鸡汤、不说教。
- `analysis` 点出具体手法，不报流派名（不说 CBT/ACT），用大白话。
- 不硬贴场景元素（风、灯、椅子），除非用户先提。
- 选项避免和示例对话撞车，避免模型逐字照抄。

### 几条反复出现的陪伴手法

| 手法 | 一句话 | 例子 |
| --- | --- | --- |
| 先接住不解决 | 默认目标是「被听到」不是「被解决」，没问「怎么办」就不给建议 | 「那先别回去。你现在火还没下去，缓一会儿。」 |
| 把今天和整个人切开 | 限定坏事的范围，不让它扩散到全部自我 | 「不是你整个人有问题，是那一会儿火太冲。」 |
| 允许沉默/允许乱 | 把「不说」「乱」列为合法状态，不急着理清 | 「那先乱一会儿。现在不用马上理清。」 |
| 拆小目标 | 把目标从「找到办法」降到「今晚能过去」 | 「今晚能过去，就已经算一点了。」 |
| 解除必须 | 把「必须回家」「必须积极」拆掉，列为可选项 | 「不回也行，先坐会儿。」 |
| 安全永远第一 | 高风险立刻退出场景，转现实救援 | 「先往里站一点。」 |

## 接口

- `GET /api/branches/{scene_id}` — 返回整棵树（前端可预取）
- `POST /api/chat/branch` — `{conversation_id, node_id?, user_label?}`，推进一个节点，返回 `companion_line / analysis / options / is_ending / ending_type / should_end`

分支模式不调大模型，离线可用；分支回复也写进会话历史，方便之后切回自由聊天时大模型有上下文。

## 前端

- 入口：「我想说两句」（自由聊天，默认）/「不知道说什么」（分支）/「我不想说话」（结束）。
- 顶栏「解析」开关：打开后每句陪伴回复下方显示 `analysis`（`.analysis` 块，`body.show-analysis` 控制显隐），状态存 localStorage。
- 分支中随时可点「我想自己说」切回自由输入；自由输入中随时可点「不知道说什么，给我选项」切回分支。
- 安全结局渲染援助热线卡片，停掉白噪音。

## 与一期的关系

自由聊天仍是默认模式和核心体验，分支只是「不知道说什么」时的引导扶手。两者共享同一套场景、角色、安全规则，互不冲突。

## 持久化降级

二期顺手把持久化层改成「尽力而为」：DB 不可写（权限/只读/沙箱）时自动降级为纯内存，统计与安全事件仍记在内存里，**不阻断陪伴主流程**。陪伴对话本身不依赖 DB。
