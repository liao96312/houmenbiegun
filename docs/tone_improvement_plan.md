## 0. 一句话结论

项目现在生硬，**不是因为模型不行，而是因为三件事**：

1. **开箱即用状态下根本没有模型**——没配 `AI_API_KEY` 时，回复是一条写死的常量，跟用户说了什么完全无关。
2. **提示词是一张禁令清单**——12 条 `style_rules` 里 10 条是「不要」，模型只知道不该做什么，不知道**可以做什么**。
3. **示例对话本身就是教练腔**——`mes_example` 是模型最强的行为锚点，而现有示例几乎全是「先别 X / 不用 Y / 今晚先 Z」的处置句，模型学到的是「处理问题」，不是「在意这个人」。

## 1. 现状体检：具体哪里生硬

### 1.1 【致命】不配 key 时，回复是一条常量，与输入无关

证据（在仓库根目录直接跑）：

```bash
python -c "
import sys; sys.path.insert(0,'.')
from app import core
s = core.scene_by_id('convenience_store_night')
for t in ['今天被裁了。我坐在便利店门口，不太想回家。','我妈妈上周走了。','楼下的猫今天死了。']:
    print(t, '->', core.ask_model(s, [], t))
"
```

实际输出（`ai_configured: false`）：

```
今天被裁了。我坐在便利店门口，不太想回家。 -> 嗯，先坐一下。先不用把事情讲清楚，坐一会儿也行。
我妈妈上周走了。                          -> 嗯，先坐一下。先不用把事情讲清楚，坐一会儿也行。
楼下的猫今天死了。                        -> 嗯，先坐一下。先不用把事情讲清楚，坐一会儿也行。
```

**用户刚说亲人去世，系统回「先不用把事情讲清楚」——这不是生硬，这是冒犯。**
位置：`app/core.py` → `ask_model()`（无 key 直接 `return fallback_reply(scene)`）+ `fallback_reply()`（拼 `fallback_prefix + fallback_suffix`）。
仓库里没有 `.env`，只有 `.env.example`，所以**这就是绝大多数人第一次打开项目时体验到的真实产品**。

### 1.2 【结构性】提示词 83% 是禁令，没有正向配方

`data/prompts.json` 的 12 条 `style_rules`：**10 条是「不要」**，只有 2 条是正向描述（「先接住具体处境」「留白」）。

模型没有拿到任何**可选动作**：不知道可以命名情绪、可以复述对方的原词、可以问一句真正好奇的话、可以给一个具体的身体动作（倒杯水、拉把椅子）。禁令只能让输出变安全，不能让输出变温暖。

### 1.3 【结构性】示例对话是「处置句」，不是「人话」

现有 `mes_example`（8 角色共 15 组）几乎全部同一结构：**「先别 + 否定 + 时间限定」**。例如：

- 「那先别回去。你现在火还没下去，缓一会儿。」
- 「先别急着定答案。今晚能过去，就已经算一点了。」
- 「今晚先别判这么大。被说两句很烦，但不等于你整个人不行。」

这些句子**逻辑都对，但每句都在纠正对方**。连续听到时，体感是「有个冷静的人在教我该怎么做」，而不是「有人坐在我旁边」。

### 1.4 【量化】句式高度同质化

对 `branches.json` + `scenes.json` 全部 106 条手写台词统计：

| 指标 | 数量 | 占比 |
| --- | --- | --- |
| 含「先」字 | 66 | **62%** |
| 含「别 / 不用」 | 44 | **42%** |
| 以「嗯」开头 | 19 | 18% |

62% 的句子带「先」，读起来就是一套流程话术。用户连续收三条「先别…」，会立刻识别出这是模板。

### 1.5 【关键缺失】没有「引用对方刚说的具体信息」这条硬要求

这是 Gemini 和本项目最大的差距。拿用户「今天被裁了。我坐在便利店门口，不太想回家。」举例：

- Gemini 接了**「台阶」**（用户给的具体物件）→「就坐在台阶上吹吹风也挺好」
- 项目 prompt 里没有任何一条要求复用用户原词，接不接得到全靠运气

用户判断「你有没有在听我」，靠的就是**你有没有捡起我刚说的那个词**。这一条缺失，是「没同理心」体感的主要来源。

### 1.6 【过度纠偏】为了反鸡汤，把温度一起删掉了

`style_rules` 同时禁掉了：夸奖、自曝经历、追问、幽默、具体关心、提场景物件。
其中「不要为了贴场景而硬提风、灯、椅子、雨」本意是防文案腔，但连**自然使用**也一起禁了——而「给你倒杯热水」这类**具象动作**恰恰是人味的主要载体（见 3.1）。

### 1.7 【角色薄】人格只有形容词，没有可执行的声音档案

`scenes.json` 的角色只有 `personality` 一句形容词（「温和，不黏人，话不多」）。缺：口头禅、怎么称呼用户、一次说几句、对沉默怎么办、绝不说的话题、标点习惯。结果就是 8 个角色说起来**只有场景名不同，声音是同一个人**。

### 1.8 【安全】分级过粗 + 模板单一 + 冷

- `risk_level_for()` 是纯关键词表，漏掉大量真实表达：「不想醒过来」「想消失」「睡过去就别醒了」「别管我了」。
- `risk_level >= 2` 直接整句替换为**同一条** `safety_reply`，**没有先共情再转介**，也没有分档措辞。用户从「被陪伴」瞬间掉进「被流程处理」。
- 热线号码没有出现在 `safety_reply` 里（README 里写了 400-161-9995 / 120，代码里没有），且未做成可配置。

## 3. 从 Gemini 身上提炼的 6 条手法（已转成可写进 Prompt 的规则）

Gemini 自己复盘出的 4 条，加上我在对照里补充的 2 条，全部配「反例 → 正例」。

### 3.1 用具象动作承接情绪，而不是流程化宽慰

> 面对坏消息时，不要对**事件**表达空洞同情，而是调用当下空间里的一个**微小物理动作**（递水、拉椅子、允许发呆）。

- ❌ 听到这个消息我也很难过，被裁员确实是一件压力很大的事，你现在的情绪是完全正常的。
- ✅ 先别急着回，就坐在台阶上吹吹风也挺好。我去给你倒杯热水，你缓一缓。

**与本项目的冲突及处理**：不是推翻 1.6 那条禁令，而是**收窄**它——禁止的是「整句场景描写」（如「雨还在下，灯光昏黄」），鼓励的是「用场景里的一个动作做承接」。建议量化：**每 3 条回复最多出现 1 次场景动作，且动作必须回应对方刚说的内容。**

### 3.2 用体感俗语点破那个滋味，禁止框架提炼

> 禁止复述用户的话来做「镜像倾听」（"听起来你感到…"），禁止心理学术语，用生活化比喻还原那种别扭感。

- ❌ 听起来你不仅感到失落，更多的是一种被隐瞒的被动感和长期的心理内耗。
- ✅ 这感觉最难受了，就像一直等着靴子掉下来，还得配合演戏。真挺折腾人的。

### 3.3 合法化眼前的停滞，禁止前瞻规划和价值重塑

> 用户提年龄 / 前途 / 迷茫时，严禁长期规划、能力盘点、正能量鼓励；把目标压缩到极短的当下一刻。

- ❌ 34 岁其实正是经验丰富的黄金期，正好可以借这个机会复盘一下核心优势，重新规划职业路径。
- ✅ 三十四怎么了，这年纪卡在中间确实让人心里发慌。今晚就先别逼自己想以后了，把今晚熬过去就算数。

**注意**：本项目已有雏形（「今晚能过去，就已经算一点了」），但它是**独立口号**，没有先接住「34」这个具体信息。正确顺序是：**先接具体信息 → 再合法化停滞**。

### 3.4 做低存在感的陪伴锚点，禁止索取反馈

> 对方情绪转好、说谢谢时，不要做正向总结，也不要追问后续（"那你接下来打算怎么办"）。申明自己在场，给对方一个无社交压力的停留空间。

- ❌ 不客气，很高兴能让你感觉好受一点。那你接下来打算怎么跟家里人说呢？
- ✅ 能顺过这口气就好。我就在这看店，你想待多久就待多久，不用硬撑着。

### 3.5 【补充】先把对方的反应正常化，再谈别的

Gemini 在「我早就觉得会被裁」那轮做了一件项目完全没做的事：**把用户的感受说成正常人都会有的**。项目是直接跳到「怎么办」。

- ❌ 那先别想那么多。今晚先休息。
- ✅ 被瞒着还得配合演戏，这谁能不憋着。

### 3.6 【补充】主动跟随用户的语速，而不是维持自己的节奏

用户只发 4 个字时，不要回 3 句；用户写了 3 行时，才值得多说一句。
项目当前固定要求「1-3 句」，没有「跟随长度」的规则，导致短输入被冗长回应碾压。

- ❌ 用户：「累。」 → 回复：「嗯，今天确实够烦的。先不用把事情讲清楚，坐一会儿也行。」（15 字输入换 24 字说教）
- ✅ 用户：「累。」 → 回复：「嗯。那就先歇着。」

## 4. 改进 Plan

### P0 — 1 天，立刻见效（不改架构，只改内容和一处分支）

#### P0-1 修掉「常量回复」这个致命 bug
**文件**：`app/core.py`
**做法**：无 key / 请求失败时，不要返回固定句，改为**基于用户原话**的模板池 + 风险分流。

```python
FALLBACK_TEMPLATES = [
    "嗯，{echo}。",
    "「{echo}」……这一下挺重的。",
    "我在。你先喘口气，{echo}这事今晚不用想完。",
    "听到了。{echo}。先不用急着说清楚。",
]

def _echo(user_text: str, limit: int = 12) -> str:
    """从用户原话里截一个自然的短片段，用作承接。"""
    t = re.split(r"[。！？!?，,\n]", user_text.strip())[0].strip()
    return t[:limit] if t else "这事"

def fallback_reply(scene: dict, user_text: str = "") -> str:
    import random
    tpl = random.choice(FALLBACK_TEMPLATES)
    return tpl.format(echo=_echo(user_text))
```

**验收**：跑 1.1 里那段脚本，「我妈妈上周走了」和「楼下的猫今天死了」必须得到**不同且贴题**的回复。

#### P0-2 把 `style_rules` 从「禁令清单」改成「正向配方 + 少量红线」
**文件**：`data/prompts.json`（并同步 `app/core.py` 的 `DEFAULT_PROMPTS` 保持结构一致）
**做法**：见第 5 节可直接粘贴的草稿。要点：保留红线，但**新增 4 类正向动作**（抓词 / 命名 / 正常化 / 在场）。

**验收**：`style_rules` 中「不要」类不超过 4 条；新增正向规则不少于 6 条。

#### P0-3 重写全部 8 个角色的 `mes_example`
**文件**：`data/scenes.json`
**做法**：每角色从 2-3 组扩到 **5-6 组**，且必须覆盖这 5 种情形：

1. 用户在倾诉一件具体事
2. 用户否定自己
3. 用户只发很短的一句 / 沉默
4. 用户在骂人 / 迁怒（不要讲道理，先站在他这边）
5. 用户说谢谢、情绪回稳
6. 用户主动问「怎么办」（这时**才可以**给建议）

**硬性要求**：每个角色至少 **2 组示例是「纯共情、零建议」**；至少 1 组示例里**出现用户刚说过的原词**。删掉现在这种「先别 X。你 Y，缓一缓。」的同构句式，改为长度不一、语气不同的自然对白。

**验收**：8 角色示例句式的首字重复率 < 30%（当前「先」字占比 62%）。

#### P0-4 加「必须捡起对方原词」的硬约束 + 反重复约束
**文件**：`app/core.py` → `build_system_prompt()`
**做法**：在 system prompt 末尾追加：

```
这一轮你必须做到（按顺序）：
1. 从用户最后一句里挑一个具体词（事件/时间/数字/称呼/身体感受），在你的回复里用上它或用它的同义说法。
2. 说出这句话底下的滋味，用大白话。不要用"听起来你…"这种句式。
3. 如果合适，把对方的反应说成正常人都会有的。
4. 不要索取反馈，不要"你现在感觉好点了吗"，不要规划未来。

以下开头本轮禁用（连续两轮不得重复同一种）：嗯 / 先别 / 其实 / 我理解 / 听起来
```

同时把上一轮的回复一起带进 prompt，让模型自己避开重复：

```python
last = next((m["content"] for m in reversed(history) if m["role"] == "assistant"), "")
if last:
    lines.append(f"你上一轮说过：{last}")
    lines.append("这一轮不要和上一轮用同一个开头、同一个句式。")
```

**验收**：连续 5 轮对话里，回复开头不得出现两次相同的前两个字。

- **P2-1 两段式生成**：先让模型输出一行「我听到了什么」（内部用，不展示），再基于它生成回复。可显著提升「接得准」的比例。

- **P2-5 前端配合**：打字机节奏随句子长度变化、允许更长的停顿；「解析」面板里把「刚才这次用了哪条手法」讲清楚（这是本项目独有卖点，值得加强）。

```json
{
```

## 6. 落地顺序

1. **P0-1（半天）** — 先把「亲人去世回同一句话」这个 bug 修掉。这是最快见效、也最不能让外人看到的一条。
2. **P0-2 + P0-4（半天）** — 换提示词 + 加抓词/反重复约束。
3. **P0-3（1 天）** — 8 个角色示例重写，这一步工作量最大但收益最高。
4. **P1-6 评测集（和上面并行）** — 没有评测集，后面所有改动都是凭感觉。
5. 再进 P1。

**回归方式**：每次改完，用 48 条探针跑一遍，重点看三个信号——
（a）回复里有没有出现用户给的具体词；（b）连续 5 轮有没有重复开头；（c）有没有出现建议/清单。

## 7. 明确不做的事

- **不追求「更热情」**。目标是「被听见」，不是「更甜」。加感叹号、加 emoji、加「抱抱」都是反方向。
- **不放开长回复**。1-3 句是资产，不是限制；要改的是**这 3 句里装什么**。
- **不引入心理学术语和疗法名**。这是当前唯一做得对且必须守住的边界。
- **不靠调 temperature 解决**。当前问题是结构（没要求抓词、示例是教练腔），不是随机性不够。
